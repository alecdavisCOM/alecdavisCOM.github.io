Cryptographic System & Implementation Auditing

Strong algorithms, wired up wrong, protect nothing. I audit the wiring.

The Mandate

Nobody breaks AES. They break the code around it — the nonce reused, the key logged, the comparison that leaks timing, the random number that wasn't. Cryptographic failure is almost always an implementation failure, and that is exactly where I look.

I audit the whole construction: the protocol design, the library choices, the key lifecycle, and the embarrassing little details that turn a sound scheme into a decorative one. For systems where a crypto flaw is existential — wallets, messengers, vaults, auth — this is the review that has to be right.

Engagement Scope
  • Protocol and handshake design review against known attack classes
  • Key generation, storage, rotation, and destruction lifecycle audit
  • Randomness and entropy-source verification
  • Nonce, IV, and padding handling review
  • Constant-time and side-channel (timing, cache) analysis
  • Library selection and misuse assessment
  • End-to-end and zero-knowledge construction verification
  • Post-quantum readiness and migration planning
How I Work

I read the code and the spec together, because the gap between them is where the bugs live. Findings are explained with the concrete attack they enable, not an abstract warning, so your engineers understand why it matters and how to fix it correctly rather than superficially.

Every engagement runs under a signed NDA and, where testing is involved, a Safe Harbor agreement. Legal and ethical, start to finish.

What You Receive
  1. A cryptographic audit report with each finding tied to a concrete attack
  2. A key-management and lifecycle assessment with corrective design
  3. A remediation and, where relevant, post-quantum migration roadmap
Questions
We use a vetted library — isn't that enough?+

A good library is necessary, not sufficient. Most real failures come from how the library is used: reused nonces, mishandled keys, leaked timing. That usage is exactly what the audit examines.

Can you review a zero-knowledge or E2E design?+

Yes. End-to-end, zero-knowledge, and multi-party constructions are core work — both the mathematical design and the implementation that has to honor it.

What does a Cryptographic System engagement include?+

It is scoped to your objective, not a fixed checklist. A Cryptographic System engagement can span 8 distinct workstreams — from protocol and handshake design review against known attack classes to constant-time and side-channel (timing, cache) analysis — and we fix the exact boundaries in writing before any work begins.

What will I actually receive?+

Concrete, usable output: A cryptographic audit report with each finding tied to a concrete attack, A key-management and lifecycle assessment with corrective design, and A remediation and, where relevant, post-quantum migration roadmap. Everything is documented to a standard your team, board, and counsel can act on — not a slide deck that gathers dust.
